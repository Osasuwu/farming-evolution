# Farming Evolution — концепция

Состояние на 2026-11-24: разбор концепции с критиками (2026-11-23) и правило сорта (2026-11-24). Термины — в [GLOSSARY.md](GLOSSARY.md), исследования — в [docs/research/](docs/research/).

## Что это

Модпак Minecraft для публичного релиза, в котором материальный прогресс идёт через биологию. Селекция растений и животных — главная механика наравне с технологиями: без выведенных линий технологии не продвигаются, а без технологий не выводятся новые линии.

Основа сборки — собственный мод селекции. Тех-моды берутся существующие и перенастраиваются. Весь код, данные и ассеты пишут ИИ-агенты; автор ставит задачи, играет и принимает внешний вид.

Масштаб: одна линия «материальный прогресс через биологию», проработанная глубоко и в био-, и в тех-части. Вширь проект не идёт.

## Игра

- **Цель игрока** в первой версии — завершить дерево технологий. Поселение со спросом жителей — кандидат после рабочей первой версии.
- **Тон**: реальные виды и одомашнивание в основе, поздняя игра — спекулятивная биоинженерия. Магии нет.
- **Взаимная зависимость** не даёт проскочить этапы: тех-уровень требует био-материала — продукта сорта, проходящего требование к сырью, — а линию, дающую его, нельзя вывести без оборудования предыдущего уровня. Цена рецептов гейтом не служит.
- **Старт осёдлый**, в любом климате. С середины игры обязательны экспедиции за климатическими уникумами. Остальные функции прогрессии закрывают несколько взаимозаменяемых ключевых культур.
- **Враждебных мобов нет.** Диких животных можно одомашнить.
- **Угрозы ферме** (сезоны, вредители, болезни, хищники) убивают посевы и поголовье. Выведенная линия восстанавливается из запаса семян или племенного стада. Без запаса она потеряна, и её выводят заново из дикого исходника; дикий исходник каждой линии, нужной для прогрессии, добывается повторно. Пока игрок в экспедиции, угрозы не срабатывают.
- **Ванильная еда убрана**: культуры, рецепты, лут. Своей системы питания в первой версии нет.
- **Одиночная игра** — цель. Код мода корректен на сервере, контента под мультиплеер нет.

## Селекция

### Наследование

Образец — Forestry: типизированные хромосомы, у каждой активный и неактивный аллель, гибридизация видов с условиями. Два отличия:

- Числовые признаки растут: мутация — случайный сдвиг значения при передаче потомку — может превысить обоих родителей. Игрок выводит значение, а не ищет готовый лучший аллель.
- Условия гибридизации включают климат и почву. Зависимость от почвы — собственное дополнение сборки; прецедент есть в AgriCraft, в Forestry его нет.

Новые виды получаются гибридизацией: вид A × вид B при нужных условиях даёт вид C. Слово «мутация» значит только случайный сдвиг признака. Список видов задан в данных сборки.

### Сорт

Сорт — свойство продукта, а не линии. Это запись в данных сборки: вид плюс область значений признаков. Линия сорту не принадлежит, она даёт продукт сорта: сорт определяется заново при каждом сборе по признакам собранного растения. Продукт — отдельный обычный предмет без данных на нём, поэтому машины и автокрафт фильтруют его по типу.

Правило записано раньше кода. В коде сейчас есть только пороги «не ниже»; пороги «не выше», выбор сорта, проверки данных, требования к сырью и список пробелов делает задача #24.

Список сортов ограничен и написан заранее. Сортов, созданных игроком, нет: набор предметов закрыт при запуске игры. Имена сортов пишут агенты в данных сборки, текстуры делаются палитрой при сборке.

#### Область сорта

- По каждому признаку сорт задаёт порог «не ниже», порог «не выше» или оба. Сторону выбирает запись сорта, а не признак: у пищевого сорта горечь «не выше 3», у пряного — «не ниже 7».
- Значения признаков целые, пороги включительные. Признак, которого в записи сорта нет, сортом не ограничен: подходит любое значение из диапазона признака.
- Области сравниваются как множества значений внутри диапазонов признаков вида. Порог обязан сужать диапазон: порог, совпадающий с краем диапазона или лежащий за ним, и пустая область (нижний порог выше верхнего) — ошибки данных сборки. Поэтому разные записи задают разные области.
- Растение подходит под сорт, когда выраженное значение каждого его признака лежит в области сорта.

#### Какой сорт получает продукт

- Один сбор даёт один предмет: продукт ровно одного сорта либо несортовой продукт.
- Области сортов одного вида могут быть вложены. Если растение подходит под несколько сортов, продукт получает самый узкий из них — тот, чья область лежит внутри областей всех остальных подходящих. Отдельного поля ранга у сорта нет: порядок следует из областей.
- Чтобы самый узкий сорт всегда был один, данные сборки проверяются. Любые два сорта одного вида либо не пересекаются, либо один вложен в другой, либо в данных есть третий сорт, область которого совпадает с их пересечением. Двух сортов одного вида с одинаковой областью быть не может.
- Нарушение — ошибка данных сборки: игра останавливается при загрузке данных, как при любой другой их ошибке. Конвейер проверок поймает то же самое раньше.
- Свойства двух сортов вместе — это третий сорт того же вида, а не новый вид.

#### Несортовой продукт

Растение, не подходящее ни под один сорт своего вида, даёт несортовой продукт вида. Это один предмет на вид, его не принимает ни одно требование к сырью.

Пробелы между сортами разрешены и осмысленны: в них игрок ловит баланс между признаками. Симулятор селекции будет печатать пробелы по каждому виду; это список для автора данных, конвейер из-за него не падает.

#### Требование к сырью

Тех-рецепт ссылается не на сорт, а на именованное требование к сырью. Требование — запись в данных сборки: вид плюс область значений признаков, заданная так же, как область сорта.

- Требование проходит сорт, а не растение. Сорт проходит требование, когда область сорта целиком лежит внутри области требования. Отсюда: сорт, в записи которого нет признака, ограниченного требованием, это требование не проходит — порог требования тоже обязан сужать диапазон.
- Выведение признака дальше требуемого рецепт не ломает: более узкий сорт внутри области требования проходит его так же.
- Данные сборки проверяются: каждое требование проходит хотя бы один сорт.
- Технически требование — тег предметов, который мод собирает из сортов при запуске игры. Машины, автокрафт и KubeJS видят обычный тег.

У игрока по-прежнему одно понятие — сорт. Требование — способ рецепта назвать сразу все подходящие сорта, а не второй вид класса у продукта. Ручной список сортов в рецепте отклонён: его пришлось бы править при каждом новом сорте, а замысел «не ниже минимума» ушёл бы из данных.

#### Пример: лён

Пример условный: в вертикальном срезе у льна один признак и один сорт. Здесь признаки льна — прочность волокна и длина волокна. Сорта:

| Сорт | Прочность | Длина |
| --- | --- | --- |
| крепкий лён | не ниже 7 | — |
| длинный лён | — | не ниже 7 |
| отборный лён | не ниже 7 | не ниже 7 |

Области «крепкого» и «длинного» пересекаются, и ни одна не вложена в другую, поэтому данные без «отборного» не загрузятся: его область и есть их пересечение.

| Растение | Подходит под | Продукт |
| --- | --- | --- |
| прочность 8, длина 5 | крепкий | волокно крепкого льна |
| прочность 5, длина 9 | длинный | волокно длинного льна |
| прочность 8, длина 8 | крепкий, длинный, отборный | волокно отборного льна — область самая узкая |
| прочность 5, длина 5 | — | несортовое волокно льна |

Требование «прочное волокно» (прочность не ниже 7) проходят крепкий и отборный лён, длинный не проходит. Линия, у которой после крепкого выведена ещё и длина, даёт отборный лён, и рецепт с «прочным волокном» принимает его по-прежнему.

#### Пример: пробел

Условный вид со съедобным семенем, признаки — горечь и жёсткость. Пищевой сорт: горечь не выше 3, жёсткость не выше 4. Пряный сорт: горечь не ниже 7. Семя с горечью 5 уже не годится в еду и ещё не годится в пряность: продукт несортовой. Тот же итог у семени с горечью 2 и жёсткостью 6. Чтобы получить пищевой сорт, игрок держит оба признака не выше порогов одновременно.

#### Геном и сорт

Семя несёт полный геном, а продукт — только сорт. Значения признаков меняются понемногу от поколения к поколению и внутри сорта, поэтому улучшение идёт постепенно, а сорт сменяется, когда значения переходят порог.

#### Упрощение и нерешённое

Осознанное упрощение: в реальности класс присваивают партии по измерению, и он зависит от года и условий. В игре сорт однозначно следует из признаков растения. Сравнение с реальной селекцией и товароведением — в `docs/research/variety-vs-grade-2026-11-24.md`.

Не решено:

- как у вида, где семя и есть продукт, отделить посадочное семя от продукта для рецептов. Решается до первого такого вида;
- к какому продукту относится сорт у вида с несколькими продуктами (волокно и семя льна). В срезе сорт относится к волокну; общее правило решается до второго сортового продукта у одного вида;
- как один рецепт принимает сорта разных видов (взаимозаменяемые ключевые культуры): требование сейчас привязано к одному виду. Решается до первого такого рецепта;
- признаки, складывающиеся из нескольких хромосом;
- связанные признаки (например, горечь растёт вместе с мягкостью, а скрещивание ослабляет связь). Это вопрос движка наследования, правило сорта от него не зависит.

### Методы селекции

Каждый следующий метод открывается оборудованием и даёт больше контроля:

1. **Отбор** из диких популяций — вслепую.
2. **Скрещивание** — анализатор показывает аллели особи и шансы исходов.
3. **Направленная генетика** — выбор аллеля.
4. **Инженерия** — точная установка.

Шансы, которые показывает анализатор, и сам бросок считает один и тот же код. Лишние особи перерабатываются в полезное.

### Растения и животные

Сначала растения. Животные идут следом на том же движке, который с первого дня проектируется под оба случая: в срез входят юнит-тесты на двуполом виде животного.

## Технологии и платформа

- **Minecraft 1.21.1, NeoForge.** Платформа зафиксирована на срез и первый релиз; на приёмке среза она пересматривается вместе с выбором мода поздней химии.
- **Хребет технологий — Create.** Первый играбельный релиз без GregTech.
- **Blaze Burner** заправляется био-топливом по своему рецепту, потому что враждебных мобов нет.
- **Удаление еды и мобов**: KubeJS, LootJS, MoreJS, модификаторы биомов, код спавна в своём моде. Каждый путь проверяется на 1.21.1, допустимые утечки записываются.

## Мир и климат

Зависимости от TerraFirmaCraft нет. Климат пишется свой, по образцу TFC: его код под EUPL 1.2 можно читать и заимствовать в мод под LGPL-совместимой лицензией. Ядро читает климат через собственный интерфейс. В срезе стоит заглушка климата с настоящими градиентами. Объём своей генерации мира решается перед этапом мира.

## Устройство мода

- Ядро селекции пишется с нуля. Движок наследования — в моде; виды, аллели, сорта, пороги и требования к сырью — данные сборки.
- Все данные сборки и набор предметов читаются при запуске игры, без `/reload`. Неизвестный вид или аллель в сохранении заменяется диким типом с записью в лог.
- Хранение генома растения и семени решается до кода, с требованием совместимости с Create. Для сортировки и хранения семян — свой блок или модуль.
- Лицензия мода совместима с LGPL-3.0. Агентам можно читать исходники Forestry Community Edition и TerraFirmaCraft.

## Как строим

### Порядок

1. **Конвейер проверок** на моде с одним тривиальным GameTest, одной командой.
2. **Пробный прогон текстур**: один шаблон, варианты палитры в моде на 1.21.1, включая варианты для сортов; приёмка автором.
3. **Вертикальный срез**, затем пересмотр платформы.

### Конвейер проверок

- Сборка, юнит-тесты, GameTest, запуск выделенного сервера с проверкой лога.
- Клиентская стадия со скриншотом. Сначала пилот: готовый способ снять скриншот внутри игры; если его нет — computer use или инструменты агента.
- Симулятор селекции без игры: сколько поколений и времени нужно каждым методом до сорта, проходящего требование к сырью; список пробелов между сортами по каждому виду.
- Проверка достижимости и циклов графа рецептов.
- Сломанный рецепт KubeJS роняет конвейер.
- Тесты наследования с фиксированным зерном.
- Веха конвейера сама проверяет три вещи: запуск сервера из Gradle на Windows, GameTest с Create и KubeJS, обычный предмет в машинах Create.

### Правила работы агентов

- Автор не пишет код руками. Агенты находят свои ошибки через конвейер; автор оценивает только ощущение от игры и внешний вид.
- Ревью обязательно, по образцу проектов redrobot и jarvis с подгонкой под этот проект.
- Правка самих проверок идёт отдельным помеченным коммитом через ревью. Такие коммиты считаются на приёмке среза.
- Дефект, не исправленный за три попытки, уходит второму независимому агенту. Если не справился и он, фича вырезается.

### Текстуры

Программная генерация из серых шаблонов и палитр. Генеративные сервисы — только для черновиков формы. Внешний вид принимает автор. Художник — запасной путь. Производные от спрайтов Mojang не используются.

### Публикация

CurseForge и GitHub, использование ИИ раскрыто. Мод публикуется отдельным проектом CurseForge раньше сборки. GitHub Releases — запасной канал. Modrinth пересматривается к релизу: его правила не допускают в публичный каталог проекты, созданные в основном ИИ.

## Вертикальный срез

Одна линия: прядильная культура (лён или конопля), признак — прочность волокна. Один сорт, одно требование к сырью, один тех-рецепт: ремень Create принимает только волокно, проходящее требование. Около часа игры.

- Еда в срезе: съедобное семя той же линии и дикие ягоды.
- Оборудование второго метода селекции собирается из валов и шестерён Create, которым ремень не нужен.

### Условия приёмки

- **AC1.** К 2027-03-01 есть играбельный срез около часа: игрок выводит линию до сорта, проходящего требование рецепта ремня, и делает с его волокном ремень Create.
- **AC2.** Линию среза можно вывести минимум двумя методами селекции.
- **AC3.** Рецепт ремня принимает только волокно сорта, проходящего требование рецепта; несортовое волокно он не принимает; стандартного рецепта ремня нет. Все три условия проверяет автоматический тест.
- **AC4.** Волокно проходит через машину Create и автокрафт без кода совместимости. Комбайн Create собирает урожай, пересаживает и выдаёт предмет верного сорта.
- **AC5.** Первый коммит кода мода содержит единую команду проверки, и она проходит на моде с одним тривиальным GameTest.
- **AC6.** Автор не пишет код руками; ревью обязательно; автор оценивает только игру и внешний вид.
- **AC7.** Симулятор показывает, что признак растёт выше стартового максимума и сорт, проходящий требование рецепта ремня, достижим каждым из двух методов.
- **AC8.** Клиентская стадия конвейера даёт скриншот игры со срезом.
- **AC9.** Проверка достижимости подтверждает: все входы рецепта ремня достижимы, дикий исходник линии добывается повторно.
- **AC10.** Тест гибридизации, зависящей от климата, проходит на заглушке климата.
